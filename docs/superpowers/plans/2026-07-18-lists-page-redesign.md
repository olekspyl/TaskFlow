# Lists Page Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Lists page (`ListsFeature.vue` and its children) a modern, polished visual design using existing Tailwind theme tokens, with zero changes to logic, composables, props, emits, or routing.

**Architecture:** Pure presentational rework. Six files change: one shared component (`VSegmentControl.vue`, confirmed single-consumer), and five files inside `src/features/listsManager/lists/` (`ListsFeature.vue`, `Filters.vue`, `MyLists.vue`, `UsersLists.vue`, `ListContainer.vue`). Each task changes template/class-only content in one file, except `ListContainer.vue` which additionally gets two new presentational `computed` properties (no behavior change).

**Tech Stack:** Vue 3 `<script setup>`, TypeScript, Tailwind CSS (theme tokens generated by `src/features/theme/utils/createThemes.ts` — classes like `bg-secondaryBg`, `text-txtPrimary`, `border-borderDefault`, `bg-elevated`, `text-muted`, `shadow-soft` resolve to CSS variables that already flip with light/dark theme).

## Global Constraints

- No changes to composables (`useListsQuery`, `useCreateList`, `useUpdateList`), API calls (`listsApi`), props, emits, or routing — verified per task by diffing the `<script>` block (only `ListContainer.vue` gets two additive `computed` properties; everything else in every `<script>` block is byte-for-byte unchanged).
- Do not restyle `VInput`, `VSelect`, or `VButton` (`src/shared/ui/common/`) — they are used app-wide. Only their existing props and surrounding layout classes may change.
- `VSegmentControl.vue` (`src/shared/ui/common/VSegmentControl.vue`) may be restyled directly — verified single-consumer: `grep -rl "VSegmentControl" src` returns only `ListsFeature.vue` and the `shared/ui/common/index.ts` barrel export.
- All colors must come from theme tokens (CSS-variable-backed Tailwind classes) except the per-list accent, which is user-chosen (`list.hexColor`) and applied via inline `style`, not a Tailwind class.
- Every task must pass `npm run type-check` before commit.
- Spec reference: `docs/superpowers/specs/2026-07-18-lists-page-redesign-design.md`.

- [ ] **Step 1: Add two presentational `computed` properties to the script**

Open `src/features/listsManager/lists/components/ListContainer.vue`. The file already imports `computed` and `ref` from `vue` (line 2) — no new imports needed. Add the two new computed properties directly after the existing `deleteOptions` computed (after line 47, before line 49 `const { loading: listDetailsLoading, ... }`):

```ts
const cardStyle = computed(() => ({
  backgroundColor: `${props.list.hexColor}14`,
  borderColor: `${props.list.hexColor}2E`,
}))

const progressStyle = computed(() => {
  const total = props.list.totalTasks
  const percent = total > 0 ? Math.round((props.list.completedTasks / total) * 100) : 0

  return {
    width: `${percent}%`,
    backgroundColor: props.list.hexColor,
  }
})
```

Everything else in the `<script setup>` block (the `actions` computed, `handleOpenList`, `handleDeleteList`, `openEditModal`, `closeEditModal`, all API/query wiring) stays exactly as-is.

- [ ] **Step 2: Replace the template**

Replace the existing `<template>` block (lines 110–135):

```vue

  <div
    class="group flex flex-col gap-3 rounded-2xl border p-4 transition-shadow duration-150 ease-out hover:shadow-[0_4px_12px_rgba(15,23,42,0.08)]"
    :style="cardStyle"
  >
    <div class="flex items-start justify-between gap-2">
      <button
        type="button"
        :disabled="listDetailsLoading"
        class="truncate text-left text-bodyEmphasis text-txtPrimary transition-colors hover:text-primary disabled:cursor-not-allowed disabled:opacity-60"
        @click="handleOpenList"
      >
```
